> README // WHAT THIS IS NOT ▸

The idea

The version the Global Consciousness Project actually measured: coherence across a network of independent generators. It never mattered what a generator "meant" — only that it was an independent source sampled continuously. So this is a swarm of independent entropy arms, each drawn fresh every second, watched for the moment they agree more than independence allows.

The live tier — what the statistic runs on

Algorithmic / null controls: a CSPRNG plus five separately-seeded PRNGs (xorshift, PCG, splitmix, mulberry, Lehmer). They are deterministic, so they cannot carry a real anomaly — they are distributed null controls. Physical detectors: CPU/clock timing jitter, the phone motion sensor (opt-in), the arrival-timing jitter of the Wikipedia / Bluesky / Mastodon firehoses (when each event lands, not its content), drand quicknet, and the Coinbase trade tape (arrival timing plus tick and size low bits — the price itself is display only). Every arm contributes to an epoch only when it has genuinely new data — no stale value is ever re-counted.

The metric

Each second, over the arms with a fresh draw: Z = Σzᵢ/√N, coherence c = Z² (χ²₁, mean 1 under independence). The walk is Σ(c−1). The same is computed separately for the physical subset (detectors) and the algorithmic subset (controls).

The p-value, and why it is not just Σ(c−1)/√(2N)

That textbook form assumes every epoch is independent of the last. That assumption is the experiment, so it is not taken on trust. The long-run variance of the (c−1) series is estimated from the series itself (Newey–West, Bartlett window) and used in place of the nominal 2. When epochs really are independent this collapses to exactly √(2N) and nothing changes; when an arm carries memory it widens the error bar instead of letting that memory read as signal. The inflation factor is shown as vif whenever it exceeds 1.05.

It is deliberately one-directional: the estimate is clamped so the correction can only ever widen the interval, never narrow it. A downward sampling fluctuation would otherwise manufacture confidence, which is the one direction this instrument must not drift. The cost is a little power — on a clean null it fires at p<0.05 about 4% of the time rather than 5%.

The one rule, instrumented

Every arm must be an independent draw — so every arm is measured for it. Each row reports its live sample count, its realised σ̂ (should be 1.00) and its lag-1 autocorrelation r₁ (should be 0), and turns amber past 4σ from either. This caught the original Coinbase arm, which emitted an EWMA z of realised volatility and so inherited volatility clustering at r₁ ≈ 0.72; with only two live physical arms that pushed the detector panel's p<0.05 rate from 5% to 12%. It now draws from trade arrival timing and tick/size low bits, like the other tape arms. No variance estimator can rescue a badly dependent arm — so the instrument says which arm is misbehaving rather than quietly absorbing it.

Detector vs control — the actual test

The two subsets use disjoint arms, so their session Z's are independent and (Z_det − Z_ctl)/√2 is itself ≈N(0,1). That difference is the hypothesis this whole instrument exists to test, so it is reported with a p-value instead of being left for the eye.

Sessions, gaps and reading several numbers at once

The session survives a reload: only running sums are stored, so a resumed session is numerically identical to one that never stopped. Reset discards it; CSV and JSON export the epoch series and the full state including every arm's diagnostics.

setInterval is not a clock — a hidden tab gets throttled, often to once a minute. A late epoch is discarded, not counted, and the backlog cleared: folding a minute of stream events into one "one-second" draw would change what the arms are measuring. Discarded gaps and the measured epoch spacing are both shown.

This page shows several statistics at once — full swarm, detectors, controls, their difference, and two fly-brain readouts. They are not independent tests and there is no correction applied across them. Do not read the smallest p on the page as if it were the only one you looked at.

The context ring — kept, but outside the math

Solar wind, seismic, barometric, tide, river, air quality, ocean swell, NIST, Hacker News and GitHub update every few minutes — far too slow for a 1 Hz statistic, where they'd just be one frozen value re-counted hundreds of times. So they ride alongside as honest, timestamped context and never touch the coherence number. (Browser-hostile ones flag "may need proxy.")

The fly brain — a second way of looking, not a second source

The statistic above reads the swarm one way: sum the arms, square it, watch the walk. That is a very specific hypothesis about what coherence would look like — everything leaning the same way at once. A real Drosophila brain solves a different problem with the same kind of input, and it is worth borrowing the shape.

Each epoch the fresh arms are injected into a 48-glomerulus antennal lobe with divisive gain control, projected onto 2000 Kenyon cells through 6 random claws each, and squeezed by a single APL-style inhibitory neuron into a ~5% sparse code — the mushroom body's random-projection hash. That code drives one MBON through synapses that depress when used and slowly recover: a pattern the brain has seen before lands on weakened synapses and produces low MBON drive. In parallel the same input drives a 16-wedge ellipsoid-body ring attractor (local excitation, global inhibition) whose bump sharpness PVA reports how directionally consistent the drive is. Parameters follow the published hemibrain / FlyWire figures; the wiring itself is redrawn from fresh entropy at every boot, because individual flies differ.

So it answers two questions the sum cannot: has this configuration happened before? (familiarity) and does the swarm point somewhere? (bump coherence).

Why it cannot manufacture coherence

Because it is not an arm. It is derived from the arms, so putting it in the statistic would be exactly the mistake the rule below forbids — it is kept strictly outside. And because it is derived, it has no analytic null: a circuit with memory has no clean χ². So every epoch an identical twin brain — same wiring, same parameters, same number of live channels — is fed matched synthetic noise, and both readouts are reported as paired differences against that live null: Z_fam from MBON_null − MBON_signal, Z_ring from PVA_signal − PVA_null. Positive means the real swarm looks more structured than matched noise.

The paired differences are not independent across epochs — the MBON depression trace and the ring attractor both carry state — so the same Newey–West correction the main statistic uses is applied here too, with the same one-directional floor.

Even so, read these two loosely. Measured against a pure null over 360 independent cold boots of 1200 epochs each, Z_fam crosses |Z|>1.96 about 6.7% of the time and Z_ring about 5.6%, against a nominal 5% — the MBON trace's memory runs to roughly 220 epochs, well past what any practical lag window recovers. So these readouts run mildly optimistic and should be treated as exploratory, not as calibrated evidence. And never multiply the two p-values together: both readouts share the same input, so they are correlated by construction.

The seed extractor

The swarm is a pile of entropy sources, so it can do one genuinely useful thing besides watching itself: hand you a seed. Press Generate and every enabled layer is folded through HKDF-SHA-256 (RFC 5869) into 128, 256 or 512 bits, on your device, with no network call and no storage.

The safety argument is the whole design. crypto.getRandomValues() is always in the input and supplies the salt, and it cannot be switched off. So extra layers can only ever add; they can never subtract. Even if every other source were fully known to an attacker — pinned to a constant, say — the output is still exactly as strong as your CSPRNG alone. That property is tested: with six of the seven layers held at a fixed byte, 400 extractions are all distinct and statistically indistinguishable from pure CSPRNG output.

This is not "more random" than your CSPRNG. Nothing is. It is less dependent on any single source — which is the only honest thing multi-source mixing buys you, and it is a real thing to want if you distrust one link in the chain.

Every source is measured, not trusted

Each layer runs the two NIST SP 800-90B continuous health tests — Repetition Count and Adaptive Proportion, at α=2−20 — plus the MCV min-entropy estimator (§6.3.1), live, on its own byte stream. Min-entropy is assessed once and then latched: the cutoffs are held fixed against that assessment, because recomputing them from the live estimate would let a failing source drag its own cutoff down with it and never trip. A source that degrades after assessment fires its test and immediately drops to claiming zero bits — it stays in the mix, since mixing cannot hurt, but it stops counting toward the total.

Public sources are counted as zero secret bits, always. drand, Wikipedia, Bluesky, Mastodon and the Coinbase tape are unpredictable in advance but anyone can watch the same events, so they add depth and independence, not secrecy. Pretending otherwise would be the same species of error as counting a deterministic PRNG as an entropy source.

A browser tab is not a safe place to make long-lived secrets — extensions, injected scripts and swap can all reach this page's memory. Do not generate wallets or production signing keys here. And note what is absent: no seed is ever served from a server, because a seed that came off a server is known to that server. Every visitor extracts their own, locally. If you want public verifiable randomness instead, that is drand's job, and drand is already one of the arms.

The keyed channel

A seed is a key, so the extractor feeds a message box. AES-256-GCM, key derived from the seed by HKDF with its own domain label, a fresh random 96-bit nonce per message, and the envelope tag SYNC1 bound in as additional authenticated data. The result is SYNC1.… — carry it however you like.

The cipher comes from WebCrypto, not from this page. The in-page SHA-256 exists so HKDF works air-gapped; a block cipher is not something to improvise. Where WebCrypto is unavailable the panel disables itself rather than quietly falling back to something weaker.

The key travels separately. That is the entire security model. Hand it over in person, read it aloud, use a different app — never down the same pipe as the messages. Compare fingerprints first: the fingerprint is derived from the key but does not reveal it, so it is safe to say out loud, and matching fingerprints mean matching keys.

There is no server here, no account and no transport, which is why you carry the blob yourself. Nothing about a message is stored: the transcript lives in the tab and dies with it.

What it is not: not a secure messenger. No forward secrecy — if the key leaks later, every message ever sent under it opens. No sender identity: anyone with the key can write messages that look like yours. Replays are not detected. Nothing protects a device already compromised. For real conversations needing those properties, use Signal. Use this to hand someone a note with no server in the middle, and rotate keys freely — a new seed is one press. A wrong key and a tampered message fail identically, which is the point of an AEAD.

The one rule, and what this is NOT

Every arm must be an independent draw — never arm B derived from arm A; that single mistake manufactures fake coherence. (Which is why the fly brain is a readout and not an arm, and why each arm's independence is measured on screen rather than assumed.) It measures coincidence, not meaning — Jung's synchronicity is what an observer reads into a coincidence; no instrument supplies that. And run long enough and you will cross p<0.05 ~1 session in 20 by chance — calibration, not a message. The "glitch" is theatre for a spike; the verdict text stays honest.
